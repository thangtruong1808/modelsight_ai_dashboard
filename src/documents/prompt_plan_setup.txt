## Step 4: Dashboard features (aim for 12-15; ship all of these across phases)
1. App shell: collapsible sidebar, topbar with search, breadcrumbs, user menu, responsive navigation (mobile drawer), light/dark theme toggle (system detection, persisted, no flash).
2. Overview: KPI cards (requests, success rate, p95 latency, error rate, cost, active models) with sparklines, deltas vs previous period, and animated counters.
3. Performance time-series: accuracy/latency/throughput charts with date-range selector, compare-to-previous-period, zoom/brush, anomaly highlighting.
4. Models registry: data table with sorting, multi-filter, search, pagination, column visibility, row selection, status badges, density toggle.
5. Model detail (drill-down): tabs (Overview, Metrics, Versions, Drift, Incidents), deep-linkable via URL.
6. Data drift monitoring: heatmap (features x time), distribution comparison chart, drift score ranking.
7. Latency and error analytics: percentile chart (p50/p95/p99), error breakdown donut/bar by type, top failing endpoints.
8. Alerts & incidents center: severity/status filters, incident timeline, acknowledge/resolve actions with optimistic updates.
9. Alert rules builder: validated form (metric, condition, threshold, window, channel) with a live preview chart of when the rule would have fired.
10. Request logs explorer: virtualized table, full-text search, filters, JSON viewer, detail side drawer, copy/export.
11. Cost & usage analytics: tokens and cost by model/team, budget progress with forecast, stacked bar and area charts.
12. Model comparison: select 2-4 models/versions and compare metrics side by side (overlay charts + comparison table with best/worst highlighting).
13. Live monitoring: simulated real-time streaming metrics (rolling chart, pause/resume, live event feed).
14. Global filters and saved views: environment, time range, model, team; state synced to URL (shareable links); saved views; export to CSV/PNG.
15. Command palette (Ctrl/Cmd+K), notifications center, keyboard shortcuts, settings/profile page, onboarding tour.
Also recommend any additional features you think add real showcase value, but keep the scope realistic.

## Step 5: UX, UI and design (highest priority)
- Define a design system first: color tokens (including semantic severity/status colors), typography scale (tabular numerals for metrics), spacing, radius, elevation, motion rules, and component states.
- Data-dense but clean and professional layout; consistent card and chart styling; charts fully themed for both light and dark mode.
- Every screen has designed loading (skeletons), empty, error (with retry) and success states. Include a toggle in settings to simulate slow network and API errors to demo these states.
- Animation with Framer Motion: page and panel transitions, chart entrance, list reordering, drawer and dialog motion; respect `prefers-reduced-motion`.
- Responsive from mobile to ultrawide (collapse sidebar, stack cards, horizontally scrollable tables with sticky columns).
- Accessibility: keyboard navigation, focus management in drawers/dialogs, ARIA labels, WCAG AA contrast, and an accessible data-table alternative or summary for charts.
- Performance: route-level code splitting, memoized chart options, virtualization for large lists, debounced search, avoid unnecessary re-renders.
